# Quality & Accessibility Checklist

## Acceptance
- User story acceptance criteria are satisfied
- Happy path works
- Relevant unhappy paths are handled
- Relevant edge cases are handled

## Application State
- Loading state is clear
- Successful content displays correctly
- Empty state is understandable
- Failure state does not crash
- User has an appropriate recovery action

## Accessibility
- Dynamic Type works on core screens
- VoiceOver provides meaningful info
- Interactive elements have meaningful labels
- Touch targets are usable
- Info does not depend on color alone
- Supported screen sizes/orientations remain usable

## Testing
- Important ViewModel/business behavior has unit tests
- Important network behavior is tested appropriately
- Existing tests pass
- Critical UI workflow remains functional

## Git / Review
- Work is completed on a feature branch
- Pull request created
- Another team member reviews the PR
- Main branch remains buildable

## Defects
- Known defects are documented
- High-priority defects are addressed before marking work Done
